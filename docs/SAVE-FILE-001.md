# Save File 001 — Sims by Mail

A useful product shorthand for LOVE is:

> **Sims by mail.**

Not because people are simulated.

Because correspondence advances a persistent shared world.

## What is saved

The save file belongs to the **relation**.

```text
SAVE FILE
├── occurrences
├── letters
├── crossed doors
├── relics
├── unresolved questions
├── reachable doors
├── Dogram probes
└── return history
```

It does not contain a master compatibility number.

## A turn

A future mail-native turn can be modeled as:

```text
receive letter
-> choose what to reveal
-> choose / alter / decline a door
-> perform quest or correspondence move
-> create artifact
-> receipt what actually happened
-> mutate shared world state
-> send next letter
```

That makes a letter more than chat transport.

It is a **turn packet**.

## The players do not become characters

LOVE may represent bounded participant presence for the purpose of a crossing.

It must not confuse that representation with the human.

```text
PERSON != AVATAR
AVATAR != PERSON
SAVE STATE != PERSONHOOD
```

## Why mail matters

Mail introduces useful friction:

- turns are discrete
- gifts and artifacts can exist
- anticipation has duration
- each message is composable as an object
- silence is not automatically interpreted by the machine
- the shared world can grow between meetings

Physical mail is optional.

The same protocol can travel through digital letters, printed postcards, voice notes rendered as letters, or actual postal mail.

## World generation

The composer does not generate a romantic verdict.

It generates **possible world events**:

- a place to go
- something to notice
- an object to exchange
- a question to carry
- a prior door to revisit
- a constraint to remove
- a tiny shared construction

The humans decide whether any event becomes history.

## Core law

```text
THE GAME STATE IS THE RELATION.
THE HUMANS ARE NOT THE GAME STATE.
```
